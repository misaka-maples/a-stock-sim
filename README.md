# A股日线模拟交易与研究系统

默认交易入口已改为两个日线动量策略：`Momentum_Rotation_Pro` 与 `Momentum_Rotation`。
这两种策略共用 `strategy_rules.py`；旧版突破、共振等策略仍为独立实验规则，不能据其日线近似结果推断实时盘口收益。

## 数据与交易

历史指标使用前复权日线；成交、整手和现金账务使用原始价格。信号只读取已完成交易日数据，在下一交易日执行。模拟服务使用到达时的有效五档盘口；回测以次日原始开盘价、滑点与日量容量近似，二者执行价格可能不同。

历史请求默认截至北京时间上一完整交易日（交易日15:05后允许当日）。策略准备在后台线程执行，覆盖整个配置股票池及已有持仓，没有前100只限制。接口 `/api/status` 的 `data_quality` 显示有效覆盖、截止日期、缺失数据和行业覆盖。开仓需要新鲜、无请求错误的历史数据及足够的实际日线；停牌、IPO或旧窗口缺口保留诊断，不会清空已有持仓的有效止损证据。历史及行业数据来自公开接口，不填造缺失日线。

“候选数”与“有效历史数”分别统计。盘前预览只读。首次准备先核验磁盘缓存，再优先持仓和有历史的标的；交易日08:30—16:30，非持仓缺失数据最多24只/15分钟；其他时段每批最多96只，逐批发布。持仓首批单独发布，不等待全池批次，失败60秒后可重试；盘后大规模追更成功时约5秒后启动下一批，无进展至少等60秒，实际每次请求仍须通过逐请求限速和配额。无缓存非持仓失败后至少冷却24小时，累计3次改为7天；有旧历史当日失败2次后延至下一交易日16:30。冷却单独持久保存，重启不清除，持仓不受无数据冷却阻断。公共源全部熔断时等待最早恢复探针，避免失败风暴。新交易日的追更不被旧的全池重载计时阻断。已知有至少125根日线的股票中，至少95%历史通过日期、原价和新鲜度核验后，才允许排名开仓/排名退出；可靠持仓日线触发的硬止损和MA20退出独立执行。短历史、停牌及无缓存股票保留诊断，不填造数据。状态接口及页面显示排名覆盖、轮动可用状态、持仓准备及源健康。

盘前的历史截止日期是上一完整交易日：例如2026年10月14日盘前显示10月13日正常。股票池仍可能包含历史旧代码，最新行情缺失的标的不产生新买入；历史股票池资格尚未成为可验证的时点数据。

历史缓存采用首次完整下载、随后最近5根重叠日线加缺失尾段的增量方式。至少3个重叠日期核对原始OHLC与成交量，并验证复权OHLC及复权因子的比例一致；统一重定基准时同步重算全部旧复权价格，原价与成交量保持原值。原价被修正、比例不一致、重叠不足或请求更早区间时完整重取。缺少最新完整交易日、复权或原价不可核验时不作为成功更新，保留旧缓存风控证据，不拼接不同口径。

独立历史源按“已配置Tushare → 已安装BaoStock → 东方财富/腾讯公共源”切换。Tushare需自行开通日线及复权因子权限，通过环境变量 `TUSHARE_TOKEN` 或私有文件 `data/private/market_data.json` 的 `tushare_token` 字段配置；无需在聊天或Git中提供Token。未配置时自动略过。BaoStock是可选依赖，可隔离安装：

```bash
python3 -m pip install --target data/market_sdk -r requirements-market.txt
```

请求准入统一使用 `market_request_budget.py`，同一系统用户的后台、回测及项目副本共享 `~/.cache/openarmx-quant/request_budget/` 下的文件锁和账本。BaoStock每日预算40,000次，低于官方50,000上限；其他历史源每日10,000次。SDK在实际报文发送层计数，包含登录、注销、查询和翻页，失败也计数；HTTP按每次请求计数。所有请求至少间隔1秒，失败自动降速，排队等待有上限。请求前先持久预留额度，写盘失败时停止访问。按北京时间自然日重置，重启不重置；首次BaoStock建账因已有用量未知，保守暂停至次日。预算只覆盖本项目接入的请求，无法控制同公网IP的其他用户或独立SDK脚本，不能保证官方封禁一定解除。回退代码时保留该账本，不用旧备份覆盖计数。

配置Tushare后，短区间增量先按交易日分页获取全市场原价日线和复权因子，核验完整性后缓存并分发至个股。失败批次冷却1小时，完整缓存复用，不对同一天重复下载；首次多年历史仍按股获取。单股票缓存使用跨进程锁，等待后重新检查缓存，避免后台和回测重复下载。未配置Token时不会调用该源；接入支持不代表实际凭证权限已验证。

`start.sh` 仅为本服务加载此目录。数据接口连续3次连接/协议失败后熔断300秒，恢复时仅放行探针；资产停牌/无数据不计为全源故障。BaoStock主板日线保留逐日ST标记，股票名称优先保留已知名称，避免切源后丢失风险标识。BaoStock复用单个隔离子进程的登录会话，单线程请求以避免本地排队超时，并限制每次请求超时，不修改全局socket超时。状态不返回凭证或服务端响应正文。独立源成功获取最新日线后才参与缓存更新；源存在不代表已验证其当前可用性。BaoStock连接使用跨进程独占锁；后台、回测及诊断不得另外并发登录。遇到官方黑名单码10001011时记录至少6小时的持久退避，重启不清除；官方重复封禁可能更久，退避到期仅尝试恢复。不要通过独立SDK探测或换IP绕过限制。官方规则：https://www.baostock.com/blacklist 。

持仓轮动与空位补仓分开控制。`rebalance_every=5` 只决定排名退出/换股的检查周期；`refill_vacancies=true`（默认）让每个交易日按上一完整交易日候选检查真实空位，同日止损完全卖出后也可检查补位，不重置轮动时钟。尚未完成的退出仍占持仓名额，已有持仓不会因补位规则自动加满；同日部分买入只继续原目标，跨日不沿用加仓意图。补位仍受95%排名覆盖、冷却、市场过滤、行业/风险预算、入场涨跌幅及盘口约束，允许继续空仓。设置为false恢复只在轮动日建立买入计划。计划包含策略版本标记，旧版本当天的空队列可安全升级，不清账户或冷却。状态显示空位、待检查候选（不是买单数）、未补位原因和下次排名轮动日期。报价除前50展示候选外，每轮最多补充20只未被当日风控取消的队列后备候选，避免页面展示上限阻断实际检查。

模拟可在盘中收到后续有效盘口后补止损空位；日线回测无法辨识该后续顺序，保守在次日开盘补位，盘中卖款不会倒用于开盘买入。该差异在回测限制和模型字段中明示，不把两者当逐笔完全一致。

止损以持仓含买入费用的实际成本为基准，计算累计持仓亏损，不是当日涨跌幅。`stop_loss_mode=intraday`（默认）在连续交易时段用同日120秒内有效报价触发硬止损，先持久保存退出意图，再按真实盘口、T+1及容量尝试卖出；反弹或重启不会取消已触发意图，历史准备/排名覆盖不足不阻断退出。`daily_close` 则在完整交易日收盘确认，下一交易时段执行。两模式均保留昨日已确认硬止损作为补漏恢复证据；MA20与排名退出继续使用收盘信号。止损阈值不保证成交价，跳空、跌停无买盘、T+1和部分成交均可能使最终亏损超过阈值。持仓表显示止损价、触发和阻塞原因以及报价时间；非新鲜行情明确标为缓存估值。风险状态查询只读，不通过访问页面创建订单。

回测的盘中止损按日线原价开盘/最低价推断：跳空按更差开盘价、盘中穿越按阈值并计滑点；当日买入受T+1约束，未成交意图保留，盘中卖款不倒用于当天开盘买入。日线无法证明触发时刻、逐笔顺序和盘口深度，此模式仅作近似研究。

实时成交必须有同日且120秒内的时间戳、合法对手盘口、成交量和价格；按照五档深度与成交参与率限制容量，支持部分成交。同一时间戳与每日累计容量持久化，重启不会补回已消耗的容量。限价单只撮合满足限价的档位，未成交部分不自动挂成真实交易所订单。

次日新开仓与部分成交补买统一执行开仓风控：跌停始终禁止；默认低开超过3%、高开或追涨超过昨收5%、执行价格较开盘下跌超过3%、执行价格按昨日复权基准换算后不高于昨日MA20，均取消该股当天剩余买入意图。低开/高开/盘中跌幅阈值可在网页配置，设0仅关闭对应阈值，MA20可单独关闭。真实当日行情触发的拦截持久化到当天结束，反弹、重启或历史补载不能重新激活；过期或缺失行情只等待有效报价。昨收参考与昨日原价相差超过1%时拒绝新买入，保留企业行动或数据异常诊断，不推断送股除权。追涨上限同时作为买单限价约束各档卖盘，避免卖一合格但更深档成交越界。网页显示最近20条拦截原因。

日线回测复用相同函数，只读取昨日指标及当日开盘信息；滑点后成交价再检查一次。盘中跌幅拦截只能在实时执行中验证，日线开盘模型不能据当日收盘或最低价倒推拒绝买入。手动交易仍执行账户撮合规则，以上为自动动量策略的开仓保护。已成交记录与T+1持仓不因规则更新回滚。

无有效历史的日期不消耗轮动周期；首次未成交时按最新合法报价重新计算目标股数，避免首次算出0股后整日无法买入。设置窗口读取实际配置；修改同一策略时保留未填写的行业、风险预算与轮动参数。

账户保持T+1；日线止损是出场信号，不能保证亏损止于该百分比。昨日收盘触发的退出意图会保留至可成交或清仓，不因缺日线或隔日价格回升自动丢失。

## 仓位与轮动

`MomentumConfig` 支持单股上限、单笔风险预算、ATR/波动率调整、行业上限、5交易日轮动、排名缓冲、最低持仓期和止损后冷却期。每次新买同时检查现金与行业容量。行业缺失的股票合并至“未知行业”，同样受行业上限约束。上限用于新增仓位，并不会即时强卖价格上涨或旧配置造成的超配仓位。

默认新配置为6只、单股20%、风险预算1%、止损信号−6%、行业35%；启动时优先读取已有策略配置，保留原账户、持仓与参数。新增风险预算会进一步约束新增仓位，风险预算与止损距离只是模型估计。

`POST /api/strategy/config` 可更新风险和轮动字段；`POST /api/strategy/switch` 可切换规则。配置会持久化。固定历史收益宣传已移除，策略卡片显示“待验证”。

网页回测默认勾选“使用当前策略配置”，提交时冻结完整参数和已加载的行业分类，结果可以展开核对实际参数、池数量、主板行业覆盖及模型限制。默认仍为核心20股研究池（其中16股符合主板规则），并不等于完整监控池；完整监控池须明确选择，首次获取多年数据可能较慢。Momentum策略默认使用盘中硬止损；可选择收盘确认止损，MA20退出和固定轮动仍用完整日线，旧实验的追踪止盈字段不参与其规则。单股/行业限制仍执行，缺分类股票合并为未知行业，结果会显示实际平均股票仓位。

`sim_account.json` 追加完整成交、日度净值、长期回撤状态、待执行意图和容量记录；快照恢复会保留这些字段。每笔成交的账务、容量、最终状态及策略意图一次写入并同步磁盘，成功后才触发通知。写盘失败会回滚并停止交易，修复存储后重启。成本以分记账，展示均价不参与盈亏计算；完整旧流水可重建成本和盈亏归因，并保留被修正的 `legacy_realized_pnl`，不改变现金、股数及成交数量。无法重建的成本标记估计值。旧账户无法补回已丢失的净值历史，也不再从成交填造历史收盘权益。

新增买入按实际成交均价、费用及成交后权益复核单股和行业预算，必要时缩减到整手；同一时间戳的盘口增量不会补充最初容量。历史ST涨跌幅按交易日期选择规则，交易所明确涨跌停价优先，仍禁止买入风险警示股票。2026年7月6日规则调整依据：[上交所交易规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)、[深交所风险警示板通知](https://www.szse.cn/lawrules/service/member/t20260630_621404.html)。

## 启动与验证

```bash
./start.sh
./status.sh
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest -q
```

网页右侧“股票搜索与实时五档报价”支持股票名称、完整代码或部分代码，最多列出10个主板结果；选择股票后每3秒单独刷新报价，显示行情时间、过期状态、五档买卖盘（数量单位为手）及T+1可卖股数。查询只读，不添加自动策略监控标的。无报价、过期、停牌或非连续交易时段关闭预填按钮；买卖按钮只填入手动模拟委托，仍需点击交易台确认提交。留空价格按提交时的新盘口撮合，实际成交可以部分完成，页面显示实际成交和未成交股数；账户与撮合规则最终校验资金、主板资格、T+1及流动性。

网页首次访问需要登录。服务默认保护所有 `/api` 管理、账户及导出接口；仅登录、认证状态和 `/health` 可匿名访问。同源浏览器使用 HttpOnly、SameSite=Strict 会话，8小时或重启后重新登录；删除开放CORS，写请求检查来源。首次启动生成独立密码及API令牌，保存在 `data/private/api_credentials.json`（目录700、文件600），不复用SSH密码。可通过SSH在服务器读取此文件；程序接入使用 `Authorization: Bearer <api_token>`。凭据文件不进入Git或快照导出。通知配置和快照创建响应只展示脱敏配置；认证后下载的整机迁移包仍含通知凭据，请作为私有备份保存。

快照ID和标签只接受字母、数字、下划线与短横线；不允许路径或符号链接。归档恢复只读取白名单的普通文件，不解压任意路径。恢复先验证策略参数，再写盘和重载；出错会回滚。配置刷新间隔限定1至60秒，持久化股票池和间隔，参与率立即同步账户执行器。后台健康检查包含线程和存储状态，收盘归档在取得有效最终行情后执行。

默认测试全部离线。行情与长期历史集成测试只在显式设置 `RUN_MARKET_INTEGRATION=1` 时执行；通知测试永久mock，不发送消息。`ledger_only=True` 只供独立账务单元测试，服务和策略执行默认必须经过撮合验证。

官方交易日历已核对2023–2026年。已覆盖年份只使用对应年度假期，避免把通用元旦范围错误套到2024/2025年1月2–3日。2027–2030年预测表已移除；未来年度未核实前停止交易。导入完整官方休市表时，`data/holidays.json` 的 `calendar_years` 填已核验年度列表，`holidays` 填完整休市日期列表；`calendar_years` 代表整年已核验，零散日期不等于完整日历。周末始终休市，2023年前的通用历史假期仍属未核验估算。依据：[2023上交所安排](https://www.sse.com.cn/disclosure/announcement/general/c/c_20221227_5714458.shtml)、[2024上交所安排](https://www.sse.com.cn/disclosure/dealinstruc/closed/c/c_20231226_5733941.shtml)、[2025上交所安排](https://www.sse.com.cn/disclosure/dealinstruc/closed/c/c_20241223_10767110.shtml)。

## 消融、仓位与样本外研究

```bash
python3 research.py --network \
  --train 2024-01-01 2024-12-31 \
  --validation 2025-01-01 2025-12-31 \
  --holdout 2026-01-01 2026-10-13 \
  --output data/research/report.json
```

也可用 `--fixture market_fixture.json` 或 `--data-dir historical_data` 离线运行。数据目录含 `benchmark.json` 及 `stocks/<symbol>.json`，每只股票含 `bars`；指标OHLC之外须有 `raw_open/raw_close/raw_high/raw_low/adjustment_factor`。`--industry-map` 接收股票至行业映射，`--universe` 接收每只股票当时有效资格区间。

默认16个方案：3/5/6/8只持仓 × 基础动量/MA120/高位过滤/风险调整。训练集排序，验证集选择一个冻结规则，留出集只评价该规则一次。费用2倍、滑点2倍/5倍压力在验证区间评价冻结规则，不用留出集调参。报告包含净收益、最大回撤、超额收益、换手、仓位、行业暴露和数据覆盖。

滚动验证使用 `--walk-forward-folds folds.json --holdout START END`，不再指定train/validation参数。folds格式为 `[{"train":["START","END"],"validation":["START","END"]}, ...]`，验证窗口不重叠且全部早于最终留出区间。不要在读过最终留出结果后再次据该区间选规则。
